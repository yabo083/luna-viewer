# draw 工具「5 分钟」归因（2026-11-18 实例实测）

结论：**不在 draw 里**。`draw` span 实际 17.9 s；5 分 13 秒里 94% 在工具之外。

| 阶段 | 起 → 止 | 耗时 |
|---|---|---|
| 用户消息入站 | 21:48:57.247 | — |
| step1 模型 → 给出 `draw{async:false}` | 21:48:57.8 → 21:49:05.8 | 8.0 s |
| 尝试 #1（请求已发出） | 21:49:05.9 → 21:49:27 | ≤21.1 s |
| **SIGTERM 杀进程（部署重启）** | 21:49:27 | — |
| 重启 ×3 | 21:49:27 → 21:52:01 | 154 s |
| 已启动但 agent 未 open，无人管未完成 tool-call | 21:52:01 → 21:53:59 | 118 s |
| wake 触发重放，尝试 #2 真画 | 21:54:00.9 → 21:54:18.8 | 17.9 s |
| 空回复 step（content 为空，仍入库） | 21:54:19.4 → 21:54:52.5 | 33.1 s |
| 图片发出 | 21:54:58 | — |

机制（源码）：
- `draw` 是一次非流式 provider 调用，无中间 span；span 只在结束时落库 → 被杀掉的尝试在 trace 里**完全不可见**。
- 未完成 tool-call 的唯一续跑点是 `agent.ts:188`（agent open 时 `trailingMissingToolCalls`），boot 不扫；且重放丢失 `routeId`（权限等级 5→2、审计 session 为空），若中间来了新用户消息则直接放弃重放。
- `background.after` 默认 180 s，且队列只在内存，重启即丢。

可改点（上游，按收益排序）：
1. 重启后主动续跑尾部未答复的 tool-call（省 ~272 s/次），或补一条 CANCELLED 结果让模型自己重来。
2. 优雅停机 drain 在飞工具；background item 落库。
3. 重放保留原作用域并加「已重放」标记，避免反复重画。
4. `draw` 给 30 s `traits.timeout` 默认转后台（前提 1、2 已做），或提示词默认 `async:true`。
5. 空回复（input/output token 双 0）不应入库，应重试。
6. `data/chatluna/temp` 产物堆积需清理策略；慢图模型显式设 `call.timeout.total`（默认 90 s）。

操作结论：**部署/重启前先确认没有在飞的 draw**；我们的插件部署应改为热重载或等 turn 空闲。
