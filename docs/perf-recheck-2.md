### 1.2 预热（按要求先冷启两次）

```bash
adb shell am force-stop $P; adb shell am start -W -n $P/.MainActivity   # 468 ms
adb shell am force-stop $P; adb shell am start -W -n $P/.MainActivity   # 470 ms
```

两次都是 `LaunchState: COLD`，仅作预热，不作为启动指标。

### 1.3 两个进程

| 进程 | 启动方式 | 用于 |
|---|---|---|
| A | 普通 `am start`（承接上面第二次冷启动） | 连接数（§2）、PSS/Graphics（§3） |
| B | `am start … --ez disable-service-auth-codes true --ez enable-dart-profiling true` | 头像回放（§4）、详情掉帧（§5） |

进程 B 的 Dart VM Service 端口从 `/proc/net/tcp` 里 uid=10369 的 `LISTEN` 行取，`adb forward` 后
以 `ws://127.0.0.1:<port>/ws` 订阅 `Timeline` 流（`Dart` / `Embedder` / `GC` / `API`）。
**profile 是 AOT：`evaluate` 一律返回 `code 113 "Debugger is disabled in AOT mode"`**，
所以 `ImageCache` 计数这一轮仍然拿不到（见 §6）。

### 1.4 帧口径（与上轮可比的定义）

上轮的「整帧跨度」= 该帧第一个 `Dart|BUILD` 起点 → 该帧 `Rasterizer::DoDraw` 结束。本轮引擎事件里
`Animator::BeginFrame` / `Rasterizer::DoDraw` 都带 `frame_number`，因此按帧号严格配对：

* 帧跨度 `SPAN_BUILD` = 该帧第一个 `Dart|BUILD` 起点 → 同 `frame_number` 的 `DoDraw` 结束（**与上轮同义**）；
* `SPAN` = `Dart|Frame` 起点（`Animate` 之前）→ `DoDraw` 结束（比上面早 0.1–0.3 ms，只作补充）；
* `BUILD_FRAME` = 该帧内所有 `Dart|BUILD` 时长之和；
* `GAP` = `Dart|Frame` 结束 → `DoDraw` 开始；
* 掉帧 = `Embedder|SceneDisplayLag`，按 `id` 去重（`ph=b` / `ph=e` 共用 id），
  与上轮修正后的口径一致；
* 订阅后先把引擎缓冲里的旧事件全部过滤掉（取 `getVMTimeline` 的最后一帧时间戳作边界），
  避免把上一次采集的尾巴算进来。

## 2. 空闲列表连接（两个 60 s 窗口，2 s 采样）

冷启动后停在会话列表静置，设备端一发脚本每 2 s 读一次 `/proc/net/tcp{,6}`，
筛 `rem_address` 结尾 `:13A4`（5028）且状态 `01`（ESTABLISHED）。

| 采样统计 | 结果 |
|---|---|
| 采样次数 | 30（19:10:46 → 19:11:46，60 s） |
| 每采样连接数 | 25 次 = 1 条，5 次 = 2 条，0 次 = 0 条 |
| 常驻本地端口 | `AAEA`，**30/30 采样都在**（SSE，未重建） |
| 窗口内出现的其他本地端口 | `A350`（第 0–2 采样，≈6 s）、`A658`（第 24–25 采样，≈4 s） |
| **新建端口数** | **2**（其中 `A350` 位于窗口开头、冷启动后的首次同步；稳定段只有 `A658` 一条） |

**判定：基本达标。** 常驻 SSE 只有 1 条且 60 s 不变；新建数从上轮「每 3–6 s 一条」降到
**60 s 内 1–2 条**，与修复 2 §3 的「活跃群聊 60 s 1–4 条」一致。要刚好 ≤1，需要该会话完全无新消息；
本窗口里群聊一直在进消息（同一时段进入详情可见 19:10 的新消息、列表行摘要随刷新变化），`A658` 与一次补表/帧后的请求吻合。

**第二次窗口**（详情返回列表、重建 SSE 后静置 6 s 再采 60 s，19:24 前后）：

| 采样统计 | 结果 |
|---|---|
| 每采样连接数 | 28 次 = 1 条，2 次 = 2 条，0 次 = 0 条 |
| 常驻本地端口 | `E888`，**30/30 采样都在** |
| 新建端口 | **1**（`EC02`，存活约 4 s） |

两个窗口合计：**稳定段的新建连接为 1 条/60 s**（窗口一另有一条来自冷启动首次同步）。

> 限制：2 s 采样只能看到存活 ≥2 s 的连接，**这是下限**；极短的请求连接可能被漏计。
> 因此「2 条」不等于「只发了 2 个请求」。

## 3. 内存：PSS 与分类（`dumpsys meminfo`）

四个测点：列表静置（60 s 采样结束后）、详情首屏（【mc服】300 条，进入 7 s）、详情滚到顶
（40× 慢档上滑，停 3 s）、退回列表（`BACK` 后 3 s）。单位 MB（KB/1024）。

| 测点 | TOTAL PSS | Graphics | Java Heap | Native Heap | Code | Stack | Private Other | System | TOTAL RSS |
|---|---|---|---|---|---|---|---|---|---|
| 列表静置 | **165.1** | **62.8** | 10.7 | 26.3 | 26.8 | 1.4 | 23.0 | 14.1 | 324.9 |
| 详情首屏 | **223.8** | **75.2** | 12.2 | 35.5 | 40.6 | 1.5 | 41.8 | 17.0 | 390.5 |
| 详情滚到顶 | **243.4** | **77.5** | 15.4 | 39.9 | 40.7 | 1.5 | 50.5 | 17.7 | 415.4 |
| 回列表 3 s | **224.5** | **77.7** | 12.3 | 39.2 | 26.9 | 1.5 | 50.5 | 16.3 | 394.3 |

上轮同口径：166.8 / 244.8 / 259.6 / 237.3 MB（Graphics 64.0 / 87.7 / 87.8 / 87.9）。

| 对照 | PSS Δ | Graphics Δ |
|---|---|---|
| 列表静置 | −1.7 MB | −1.2 MB |
| 详情首屏 | **−21.0 MB（−8.6%）** | **−12.5 MB（−14.3%）** |
| 详情滚到顶 | **−16.2 MB（−6.2%）** | **−10.3 MB（−11.7%）** |
| 回列表 | **−12.8 MB（−5.4%）** | **−10.2 MB（−11.6%）** |

**判定：改善，但仍未达标（目标 120 MB）。**

* 详情三项降 12–21 MB，方向与修复 2 的预估一致（预估 Graphics 70–75，实测 74.0–77.7；

  这是下一步要找的大头（Dart 堆、Skia/Impeller 缓存都记在这里，本轮无法再细分）。
* 列表态几乎没有变化：列表只有头像和少量缩略图，48 MiB 上限对它不是约束
  （修复 2 预估 PSS 150–158 / Graphics 52–58，实测 165.1 / 62.8，均高于预估）。

## 4. 头像稳定性（回放 + 截图对比）

会话：【mc服】牛马梦想家会所（300 条，含照片头像与图片气泡）。步骤：

1. 从列表进入详情，静置 8 s；
2. 设备端 `screenrecord --time-limit 24 --bit-rate 6M`（1080×2400，24.0 s，1389 帧）；
3. 快速上下交替滑动 10 次（每次 120 ms 手势 + 0.12 s 间隔），随后再滑一次回落、停在 18:50 附近的静止位置；
4. 稳定后连续截图 3 张，间隔 2 s；
5. 全程并行每 2 s 采样一次到 `:5028` 的 ESTABLISHED 连接。

### 4.1 三张截图（2 s 间隔）

| 对比 | 全帧差异像素 | 头像列（x 20–200）差异像素 |
|---|---|---|
| s1 vs s2 | 0.031% | **0.000%** |
| s1 vs s3 | 0.033% | **0.000%** |
| s2 vs s3 | 0.019% | **0.000%** |

差异像素极少（0.02–0.03%）且全部在头像列之外；**头像列逐像素一致**，没有「空白→出现」的闪烁。
最终画面里头像（C.N.S.A / Noah 等照片头像）完整渲染，与滑动过程中的帧一致。

### 4.2 录屏抽帧（2 fps，48 帧）

* 抽帧覆盖了整段滑动（约第 25–42 帧）与回落后的静止段；
* 滑动中的头像均为完整图片（例：粉色头发 `Alzhang2025`、`C.N.S.A`、`Noah`），没有出现占位渐变/空白圆；
* 滚动经过「同一发送者连续消息」区间时头像列本来就没有元素（头像只在每组第一条显示），
  该区间的低方差不是头像被清空。

### 4.3 请求侧

滑动窗口（20 s 采样，10 个采样点）：常驻 2 条（详情平台流 + `/live`，本地端口 `9AEA` / `9AF2` 全程不变），
只有 1 条短暂出现的第三个端口（`9BEC`，约 4 s）。
即 10 次快速上下滑**没有引发成批的新建连接**——若头像被反复淘汰重下，应看到多条短连接轮换。

**判定：稳定（相对上轮的用户观察改善）。** 证据链：截图逐像素一致 + 录屏无空白头像 + 连接数不随滑动增长。
无法给出的更强证据：`ImageCache.currentSize/currentSizeBytes`（AOT 不能 evaluate），
以及「同一 URL 的 GET 次数」（需要 tcpdump/root 或服务端日志）。

## 5. 详情「首屏 → 首次翻到顶」掉帧（只跑 1 次）

从列表**重新进入**该会话（首屏 50 条），1.5 s 后开始采集，随后 40× `input swipe 540 500 540 2250 35`，
间隔 0.26 s（快档，≈17 s），到达当日第一条（16:08，`今天` 分隔符）。

| 指标 | 本轮 1 次 | 上轮快档 3 轮 | 基线 |
|---|---|---|---|
| 帧数 / 窗口 / fps | 1575 / 19.44 s / 81.0 | 1373–1399 / 15.6 s / 87.9–88.9 | 1699 / 17.9 s / 95.1 |
| 单段 build p50 / p95 / max | 0.09 / 0.91 / **3.86 ms** | — / — / 3.39–8.41 | 0.69 / — / 13.58 |
| 每帧 build 合计 p50 / p95 / max | 0.08 / 1.35 / **8.31 ms** | — / — / 7.47–8.98 | — |
| 光栅 p50 / p95 / p99 / max | 2.39 / 4.15 / 5.26 / 20.64 | 3.25–3.81 / 3.97–4.96 / 5.16–7.87 | 3.50 / 4.25 / 6.54 |
| 整帧跨度 `SPAN_BUILD` p50 / p95 / p99 / max | 3.06 / **7.04** / **8.69** / 21.35 | 3.10–3.27 / 6.18–6.32 / 7.24–9.24 | 3.25 / 4.52 / 6.14 |
| `GAP`（UI 完 → 光栅起）p50 / p95 / p99 / max | 0.09 / 0.39 / 1.02 / 5.51 | — / 1.6–2.6（p95） | — |

**掉帧时间分布**：15 个 `SceneDisplayLag` 全部落在采集开始后的 **0.02–7.7 s**，
即翻页前段（首屏图片首次解码/下载的区间）；之后约 11.7 s 的连续滑动没有掉帧。
「首屏 → 顶部」整段只有前 6 s 有抖动，这与掉帧来自图片解码而不是列表构建的结论一致。

**判定：轻微上浮，未回归。**

* 0.95% vs 上轮 0.36–0.80%：超出上轮区间约 0.15–0.6 个百分点；但同轮 fps 只有 81.0（上轮 88），
  设备在这轮采集时更忙（群聊持续进消息、图片解码），且所有掉帧集中在首屏图片加载段。
* 相对基线 2.2% 仍改善约 2.3 倍；单帧 build 峰值 3.86 ms、每帧合计 8.31 ms，**全部在 11.1 ms 预算内**，
  没有出现上轮之前 13.6–23.7 ms 的 build 尖峰。
* 整帧跨度 p95 7.04 ms 比上轮（6.18–6.32）差约 0.7 ms，p99 8.69 仍在 7.24–9.24 区间；
  `GAP` 的 p99 只有 1.02 ms（上轮同一位置 p99 11.9–16.3 ms），说明差值不在
  「UI 完成 → 光栅开始」的排空间隙；推测与本轮整体帧率更低（81 vs 88）有关，未做对照实验。

## 6. 未测到 / 限制

| 项 | 原因 |
|---|---|
| `ImageCache.currentSize` / `currentSizeBytes` / `liveImageCount` | profile 是 AOT，VM Service `evaluate` 返回 `code 113 Debugger is disabled in AOT mode`（本轮实测确认，上轮是「未验证」） |
| 同一头像 URL 的 GET 次数 | 未 root，`tcpdump` 不可用；只能以 2 s TCP 采样近似，且是下限 |
| `dumpsys gfxinfo … framestats` | 未再复跑；已知结论：Flutter/Impeller 不进 HWUI，恒为 0 帧 |
| 掉帧的多次重复 | 按任务要求只跑 1 次，无法给区间 |
| 会话数 100+ 的列表虚拟化 / `cacheExtent` A/B | 与上轮相同：设备上只有 7 个会话，本轮不在验收项内 |
| 页面细节的逐帧头像检查 | 录屏 2 fps 抽帧（48 帧），短于 0.5 s 的闪烁可能落在两帧之间；用三张静止截图 + 连接采样补强 |
