## 1. 背景

ChatLuna Mobile 是 ChatLuna v2 的 Android 客户端（Flutter，arm64，个人自用，非公开上架）。它连接自建的 ChatLuna v2 实例，把 QQ 私聊/群聊作为一个 IM 客户端来浏览：消息时间线、实时生成状态、工具调用进度、图片与框架消息（记忆、后台任务）。

**功能已完整实现**：会话列表、会话详情、实时流（`/live` + 平台消息流）、中止生成、本轮计时（骨架气泡）、工具阶段耗时、媒体自托管、模型切换、会话详情面板、连接配置、明/暗/跟随系统主题。现在只差视觉品质。

用户（开发者本人）审美取向：克制、密度高、反对装饰性噪音；界面要像**做完的产品**，不是 Material 模板拼装。

## 3. 当前界面盘点（现状参数）

### 3.1 会话列表
- AppBar：标题「ChatLuna」+ 主题切换 + 菜单（断开/关于）
- 每行：会话头像 40dp（群=群头像，私聊=对方头像）+ 标题 + 副标题（平台 · 未读数）+ 右侧时间 + 未读圆点
- 未加载会话：副标题「未加载」，状态点灰色
- 已知视觉问题：行与行之间没有分组感；未读圆点与状态点视觉权重相近；时间与副标题字号接近，扫读时找不到重点。

### 3.2 会话详情（核心页面）
- 顶部信息栏（单行胶囊组）：bot 头像+名 / 模型名 / 状态灯（待机·灰点、思考中·主色呼吸、回复中·主色静止、轮询中）
- AppBar：返回、标题（会话名 + 下拉箭头）、中止按钮、更多菜单
- 时间线：`reverse: true`；消息气泡
  - 外发：主色背景 `scheme.primary`，白字，宽 ≤ 屏宽 86%
  - 接收：`surfaceContainerHighest`，正文色
  - 气泡圆角：`16/16/16/4`（靠说话人一侧上角 4）；内边距 `12,8,12,7`
  - 气泡脚注：`HH:mm`，可选 `· 用时 4.9s`，10sp，弱化色
  - 头像 32dp，连续消息合并头部（5 分钟窗口）
- 中间块（框架消息）：居中卡片，无说话人，弱底色 + 细描边，含可折叠长文（`· N 行`）
- 骨架气泡：bot 侧，宽度 60%，2 条灰条 + 流光，1px `primary @38%` 描边，**计时标签骑在描边上**（`25.4s · draw 21.6s · 思考 3.3s`，11.5sp 等宽 muted，标签底色 = 消息区底色以压断描边）
- 空态：「插件还没有这个会话的消息」居中一段灰字
- 已知视觉问题：主色大面积铺在气泡上，导致「工具阶段」「中止」「状态灯」三类主色信息互相抢；骨架边框接近告警色，看起来像错误态；信息栏三个胶囊并排，密度高、字号小（11sp），与 AppBar 之间缺少呼吸；气泡与中间块、骨架三者的圆角/描边/底色不成体系。

### 3.3 其它
- 连接页：URL + token 输入 + 连接按钮
- 模型选择：底部弹层，按 provider 分组，勾选当前模型
- 会话详情面板：底部弹层，显示会话 id、模型、轮次统计
- 阶段明细面板：本轮各阶段耗时（`draw ×2 51.4s` + 各次耗时）

## 4. 要解决的视觉问题（按优先级）

1. **信息层级**：一屏里主色出现 4 次以上（气泡、状态灯、描边、按钮），没有主次。需要一套「主色只出现在该出现的地方」的规则。
2. **字体节奏**：当前字号 10/11/11.5/15 混用，行高随意。需要定义 type scale（含 4 档用途说明），并给出每处的映射。
3. **间距系统**：现有 2/3/4/6/7/8/12/16/20 全在用。收敛成 4 的倍数体系，给出每个容器/组件的 padding 值。
4. **组件一致性**：气泡、中间块、骨架、弹层卡片四种容器，圆角/描边/底色/阴影各自为政。给出一张「容器规范表」。
5. **状态表达**：状态灯、未读点、未加载点、骨架描边四者都在表达状态，视觉语言不统一。
6. **明色主题**：目前基本只调了背景色，light 下主色气泡与背景对比不足，需要专门给出 light 的取值。

## 7. 开放式独立评审（与视觉方案分开写）

请读代码后回答，结论要能指到文件与函数；不要泛泛而谈：
